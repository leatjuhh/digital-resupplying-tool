# Sessie 13 juli 2026 - Power of Ten engineeringstandaard + Fase 0 baseline

> Ingevuld overdrachtsdocument volgens het sjabloon in
> `docs/engineering/AI_SESSION_HANDOFF.md`. Bedoeld zodat een volgende sessie
> (Codex/GPT/Claude) direct kan verdergaan zonder de volledige geschiedenis te
> hoeven reconstrueren.

## Doel van de wijziging

Twee doelen, achter elkaar uitgevoerd:
1. Een blijvende, projectspecifieke engineeringstandaard vastleggen op basis van
   `docs/references/P10.pdf` (Holzmann, "The Power of Ten"), plus een
   production-readiness audit, een gefaseerd verbeterplan en een AI-instructielaag.
2. **Fase 0 (baseline en bescherming)** uit het verbeterplan volledig uitvoeren —
   de veilige, niet-destructieve voorbereidingsstappen — en daarna gecontroleerd
   pauzeren.

## Onderzochte bestanden

- P10.pdf: volledig geëxtraheerd (6 pagina's, alle tien regels + rationale).
- Stack/architectuur: `backend/main.py`, `backend/database.py`, `backend/db_models.py`,
  `backend/routers/*` (m.n. `pdf_ingest.py`, `auth.py`, `batches.py`, `articles.py`,
  `redistribution.py`, `settings.py`), `backend/redistribution/*` (m.n. `algorithm.py`,
  `bv_config.py`, `store_profiles.py`), `backend/auth.py`, `backend/pdf_extract/pipeline.py`,
  `backend/algorithm_import/*`, `frontend/lib/api.ts` + `api-client.ts`,
  `frontend/next.config.mjs`, `frontend/tsconfig.json`.
- Kwaliteit/ops: `.gitignore`, `requirements.txt`, tests (`backend/test_*.py`),
  `tests/browser/smoke.spec.ts`, afwezigheid van `.github/` en lint/typecheck-config.
- Bestaande instructielaag: `AGENTS.md`, `.clinerules`, `CONTRIBUTING.md`,
  `docs/DOCUMENTATION_GUIDELINES.md`, `docs/PROJECT_CONTEXT_INDEX.md`.

## Genomen ontwerpbeslissingen

- Eén canonieke bron: `docs/engineering/PRODUCTION_ENGINEERING_STANDARD.md`; alle
  andere instructiebestanden (AGENTS/CLAUDE/ChatGPT/.clinerules) zijn adapters die
  ernaar verwijzen en geen eigen regels definiëren.
- Elke P10-regel vertaald met classificatie (letterlijk / aangepast / principe /
  n.v.t.) i.p.v. letterlijk overnemen van de C-regels.
- Root-markdown-whitelist geharmoniseerd naar 7 bestanden (4-vs-5-conflict tussen
  `.clinerules` en `DOCUMENTATION_GUIDELINES.md` expliciet opgelost; laatstgenoemde
  is nu de bron).
- Fase 0.6 (test-DB-isolatie): de plan-aanname "geen wijziging aan database.py"
  bleek onhaalbaar omdat `database.py` het pad hardcodeerde. Gekozen voor de
  root-cause-fix: `database.py` leest nu optioneel `DATABASE_URL` (default =
  huidige `backend/database.db`), backward-compatible, plus een `conftest.py` die
  tests naar een wegwerp-DB stuurt. Alternatief (monkeypatch van engine/SessionLocal
  in conftest) verworpen wegens fragiliteit.
- Bewust NIET gedaan: de seed-afhankelijke integratietests "groen forceren" (zou
  DB-seeding vereisen, buiten de veilige scope), git-historie herschrijven en
  secret-rotatie (destructief/operationeel — vereist eigenaarsbesluit).

## Uitgevoerde commando's

In een verse virtualenv (`pip install -r backend/requirements.txt -r backend/requirements-dev.txt`),
werkmap `backend/`:
- `python -m pytest test_bundle_planner.py test_store_sorting.py test_situation_classifier.py test_offline_situation_evaluation.py test_algorithm_import_service.py test_proposal_data_mapping.py -q`
- `python -m pytest test_algorithm_import_router.py test_dashboard_summary.py test_user_store_assignments.py -q`
- Isolatiechecks: import van `database` met en zonder `DATABASE_URL`; testrun-controle dat `backend/database.db` niet ontstaat.

Frontend (werkmap `frontend/`): `npm ci`, `npx tsc --noEmit`, `CI=true npm run lint`, `npm run build`, `npm audit`.

## Testresultaten

- Backend unit-baseline (6 bestanden): **37 passed, 2 skipped** (de 2 skips zijn
  seed-afhankelijke integratietests in `test_situation_classifier.py`). Vóór deze
  sessie: 37 passed, 2 failed.
- `test_bundle_planner.py`: 9 passed; `test_store_sorting.py`: 16 passed.
- De 3 httpx-tests collecteren en draaien nu (httpx toegevoegd). Zij **falen** nog
  op ontbrekende geseede data (bv. `login("admin",...)` → 401): dit zijn
  integratietests die een geseede DB vereisen — bekend, buiten Fase 0-scope.
- Frontend: `tsc --noEmit` → 2 typefouten (TS2339, `batch_name` op
  `BatchWithProposals`) die via `next.config.mjs` `ignoreBuildErrors: true` de build
  passeren; `npm run lint` faalt (geen ESLint-config); `npm run build` slaagt;
  `npm audit`: frontend 7 (2 moderate, 5 high), root 1 critical.
- Test-DB-isolatie geverifieerd: `backend/database.db` wordt tijdens een testrun
  (ook een die `main` via TestClient importeert) niet aangemaakt.

## Openstaande risico's

- **Critical (nog niet opgelost, staan in Fase 1):** muterende endpoints zonder
  auth (PR-001), hardcoded `SECRET_KEY`-fallback (PR-002), path traversal via
  upload-filename (PR-004). De gelekte DB-backups zijn uit tracking (PR-003), maar
  **staan nog in de git-historie** — historie-herschrijving + secret-rotatie zijn
  aparte, met de eigenaar af te stemmen vervolgacties.
- Seed-afhankelijke integratietests (dashboard, algorithm_import_router,
  user_store_assignments, en 2 in situation_classifier) draaien pas na een geseede
  test-DB-fixture (uitbreiding op Fase 0.6).
- Backup-tag `backup/pre-p10-standard` kon niet naar de remote (proxy 403 op
  tag-refs). Pre-P10-toestand blijft herstelbaar via `origin/main` = `dafc096`.

## Update — Fase 1 uitgevoerd (zelfde sessie, 2026-07-13)

Fase 1 (kritieke risico's) is daarna volledig op deze branch uitgevoerd, in 6
kleine commits, elk met test en verificatie:

1. Auth/permissies op alle 11 muterende endpoints (PR-001).
2. `SECRET_KEY` verplicht, fail-fast, geen fallback; `check_secret_key.py` print
   de sleutel niet meer (PR-002).
3. Upload-filename-sanitisering (path traversal geblokkeerd) + 25 MB
   groottelimiet; `batches.py` lekt geen exception-tekst meer (PR-004/005/014).
4. Idempotente proposal-approve (PR-006).
5. Refresh-tokenhandler smal gemaakt; serverfouten niet meer als 401 (PR-008).
6. `ALLOWED_ORIGINS` daadwerkelijk op CORS toegepast (PR-009).

**Testresultaat:** `backend/test_security_hardening.py` = 29 passed; volledige
runbare suite (unit + security) = **66 passed, 2 skipped**; de echte
`backend/database.db` wordt door de testrun niet aangemaakt (isolatie intact).

**Bewust uitgesteld (met reden):** transactiegrens bij multi-file ingest (PR-007,
vergt productbeslissing over "partial success") en de unique constraint op
`ArtikelVoorraad` (PR-006-ingestdeel, vergt data-audit op bestaande duplicaten).
Articles-CRUD is achter `get_current_active_user` gezet (alleen-ingelogd); een
dedicated `manage_articles`-permissie is een aparte vervolgstap.
